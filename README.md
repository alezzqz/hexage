# Hexage

Hexage хранит конфиденциальные текстовые заметки в зашифрованном контейнере.
Для обычной работы нужны только приложение и пароль хранилища.
Чтобы узнать назначение кнопки, наведите на неё курсор или перейдите к ней
клавишей Tab. Кнопку в фокусе можно нажать пробелом.
Окна заметок, облачного хранилища и «О программе», как и диалоги,
блокируют ввод в родительском окне, пока открыты.

Иконки: [Icons8](https://icons8.com), набор [Windows 11 Color](https://icons8.com/icons/fluency).
Иконки входят в сборку и доступны офлайн; ссылка на автора есть в окне
«О программе».

## Запуск

Целевые платформы — Windows 11 и Linux с Tk 8.6 или 9.0 и поддержкой Xft,
например Ubuntu 24.04.
Поддерживаемый диапазон приёмки — CPython 3.11–3.13. В установщике Python
для Windows включите Tcl/Tk. Для системного Python на Debian и Ubuntu
установите `python3-tk` и `python3-venv`.

Интерфейс и текст заметок используют один и тот же шрифт из доступных
семейств с латиницей и кириллицей: Segoe UI на Windows, затем DejaVu Sans,
Noto Sans, Liberation Sans и другие. Моноширинный шрифт Tk остаётся
без изменений. На Windows приложение учитывает системный масштаб экрана при
запуске. При переносе окна на монитор с другим масштабом Windows может
растянуть его изображение.

На Linux Tk должен быть собран с поддержкой Xft и fontconfig, иначе Tk видит
только устаревшие X11-шрифты и не может открыть системные TTF. Такой Tk
поставляется с системным `python3-tk`. В CPython, установленном через `uv`,
Tk может быть собран без Xft; тогда Hexage выводит предупреждение в stderr,
а текст отображается запасными X11-шрифтами. Проверить сборку Tk можно так:

```bash
.venv/bin/python -c "import tkinter as tk; r = tk.Tk(); print(r.tk.eval('tk::pkgconfig get fontsystem')); r.destroy()"
```

Значение `xft` означает поддержку системных шрифтов, `x11` — только
устаревшие. Для полноценного отображения запускайте и собирайте Hexage с
Python из дистрибутива, у которого установлен `python3-tk`.

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python -m tkinter
.venv\Scripts\python -m hexage
```

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m tkinter
.venv/bin/python -m hexage
```

Проверки из окружения проекта — `python -m pytest`, `python -m ruff check .`
и `python -m ruff format --check .`.
Синтетическая проверка Tk в графическом сеансе — `python -m tests.gui_smoke`.
Она записывает тестовую строку в системный буфер обмена и очищает его.

## Установка на Linux

### Готовый бинарник

Пользователю не нужен Python: Tk и зависимости входят в исполняемый файл.
Сначала соберите бинарник (см. «Сборка исполняемых файлов»), затем
установите его глобально:

```bash
bash scripts/install-linux.sh
hexage
```

Скрипт копирует `dist/linux/hexage` в `/usr/local/bin`, лицензии — в
`/usr/local/share/doc/hexage`, иконку и ярлык — в `/usr/local/share`.
Для записи в `/usr/local` скрипт при необходимости запросит `sudo`.
Другой каталог задаётся `--prefix`, другой бинарник — `--binary`,
удаление — `--uninstall`, отказ от ярлыка — `--no-desktop`.
Для установки только для текущего пользователя:

```bash
bash scripts/install-linux.sh --prefix ~/.local
```

Если каталог установки не входит в `PATH`, скрипт подскажет, что добавить.

Шрифты зависят от Tk, с которым собран бинарник. Релизная сборка проверяет
наличие Xft и не создаёт бинарник с устаревшими X11-шрифтами, поэтому
установщику не нужно «лечить» шрифты на машине пользователя.

### Из исходников

Нужен Python 3.11–3.13 и Tk с Xft. Пакеты:

**Ubuntu 24.04 / Debian**

```bash
sudo apt install python3 python3-venv python3-tk
```

**Fedora**

```bash
sudo dnf install python3 python3-tkinter
```

**Arch**

```bash
sudo pacman -S python tk
```

Используйте системный Python: для него пакет `python3-tk` даёт Tk с Xft.
Python, установленный через `uv python install`, может содержать Tk без
Xft. Чтобы venv использовал системный интерпретатор:

```bash
uv venv --python /usr/bin/python3.12
```

Проверить окружение и создать `.venv`:

```bash
bash scripts/setup-linux.sh --check
bash scripts/setup-linux.sh
.venv/bin/python -m hexage
```

Скрипт не запускает `sudo` и не ставит системные пакеты. Он проверяет
версию Python, наличие `tkinter` и `fontsystem`, создаёт `.venv` и
устанавливает `.[dev]`. Флаг `--build` добавляет `.[build]`,
`--python PATH` выбирает интерпретатор. Если `.venv` уже существует,
скрипт по умолчанию использует его Python. При Tk без Xft скрипт печатает
команды для дистрибутива и завершается с ошибкой.

Вручную:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m tkinter
.venv/bin/python -m hexage
```

Диагностика шрифтов и действия при `fontsystem=x11` описаны в разделе
«Запуск».

## Сборка исполняемых файлов

Собирайте на целевой ОС и архитектуре. Скрипты используют PyInstaller
из `.venv` и создают один исполняемый файл. Python получателю не нужен.
Скрипты кладут рядом с исполняемым файлом `LICENSE` и `LICENSE.GPL-3.0`;
распространяйте их вместе с программой, как требует LGPL.
[Документация PyInstaller](https://www.pyinstaller.org/en/stable/operating-mode.html)

На Windows используйте окружение с Tcl/Tk:

```powershell
.venv\Scripts\python -m pip install -e ".[build]"
.\scripts\build-windows.ps1
.\dist\windows\Hexage.exe
```

На Linux установите Tk с Xft для сборочного Python и `binutils` (нужен
`objdump`). Скрипт проверяет, что Tk сборочного Python слинкован с Xft,
и останавливает сборку, если это не так: иначе бинарник получит
устаревшие X11-шрифты. Осознанный обход — `--allow-legacy-tk`.
Скрипт также проверяет, что после импорта `hexage` сборочный Python создаёт
TLS-контекст, поэтому сборка с несовместимым OpenSSL не выпускается.
В сборку добавляется runtime-hook `scripts/openssl_runtime_hook.py`: он
задаёт `OPENSSL_CONF` раньше хуков PyInstaller, которые импортируют
`setuptools` и инициализируют TLS.
Для совместимости с несколькими дистрибутивами собирайте на самом старом
из целевых дистрибутивов с glibc.

```bash
.venv/bin/python -m pip install -e '.[build]'
bash scripts/build-linux.sh
./dist/linux/hexage
```

Путь к другому сборочному Python задаётся параметром `-Python` на Windows
или переменной `HEXAGE_BUILD_PYTHON` на Linux.

## Снимки и восстановление

После первого запуска создайте хранилище или восстановите его из локального
файла кнопкой «Восстановить» либо из окна «Облачное хранилище», если настроен
провайдер. Активный файл лежит в каталоге данных Hexage
(`%LOCALAPPDATA%\Hexage` или `${XDG_DATA_HOME:-$HOME/.local/share}/Hexage`).
«Восстановить» открывает выбор локального файла, а «Экспортировать» сохраняет
снимок в новый файл по выбранному пути. Восстановление позволяет вернуться к
старой ревизии или открыть снимок другого хранилища. Hexage проверяет снимок
и запрашивает подтверждение перед заменой активного хранилища.
При замене существующего снимка и смене пароля зашифрованная резервная
копия сохраняется рядом с активным файлом под именем `backup-*.hexage`.

Если активный файл повреждён и его невозможно открыть, закройте приложение,
переместите этот файл в отдельное безопасное место и восстановите снимок
через стартовый экран. Для открытия снимка нужен пароль, действовавший на
момент его создания. Без пароля восстановление невозможно. Экспортируйте
копию после смены пароля, если хотите использовать новый пароль на другом
устройстве. Старые снимки сохраняют прежний пароль и могут содержать
удалённые заметки.

## Облачный обмен

Можно настроить один или оба провайдера. Регистрация выполняется в браузере,
а Hexage читает параметры из файла `hexage.yaml` при запуске. Файл с пустыми
полями создаётся автоматически при первом запуске.

### Google Drive

1. В Google Cloud Console откройте список проектов и нажмите **New Project**.
   В поле **Project name** введите `Hexage` и нажмите **Create**. Выберите
   этот проект и включите **Google Drive API** кнопкой **Enable**.
   [Проекты Google Cloud](https://console.cloud.google.com/projectselector2/home/dashboard) ·
   [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com)
2. Откройте **Google Auth Platform → Branding**. Если видите **Get started**,
   нажмите его. Введите `Hexage` в **App name**, выберите свой адрес в
   **User support email**, для личного аккаунта выберите **External** и
   введите свой адрес в **Contact Information**. Подтвердите условия
   и нажмите **Create**.
   [Branding](https://console.cloud.google.com/auth/branding)
3. Если статус приложения **Testing**, откройте **Audience → Test users →
   Add users**. Введите адрес Google-аккаунта, чей Диск будет использоваться,
   и сохраните. При входе из Hexage выберите именно этот аккаунт.
   [Audience](https://console.cloud.google.com/auth/audience)
4. Откройте **Data Access → Add or remove scopes**. Выберите
   `https://www.googleapis.com/auth/drive.appdata` (при необходимости
   вставьте адрес в **Manually add scopes**). Нажмите **Update**, затем
   **Save**. Это право доступа к данным приложения на Диске.
   [Data Access](https://console.cloud.google.com/auth/scopes) ·
   [Папка приложения Drive](https://developers.google.com/workspace/drive/api/guides/appdata)
5. Откройте **Clients → Create client**. В **Application type** выберите
   **Desktop app**, в **Name** введите `Hexage Desktop`, нажмите **Create**.
   Hexage сам формирует адрес возврата на `127.0.0.1` со свободным портом.
   [Clients](https://console.cloud.google.com/auth/clients) ·
   [OAuth Desktop](https://developers.google.com/identity/protocols/oauth2/native-app)
6. Скопируйте **Client ID** (обычно заканчивается на
   `.apps.googleusercontent.com`) в поле `oauth.google.client_id`.
   Если Google требует **Client secret** при обмене кода, задайте выданное
   значение в поле `oauth.google.client_secret`. При скачивании JSON возьмите
   значения из `installed.client_id` и `installed.client_secret`.
   Hexage читает эти поля из YAML, поэтому путь к JSON указывать не нужно.

### Яндекс Диск

1. В кабинете Яндекс OAuth нажмите **Создать приложение → Для авторизации
   пользователей** или откройте форму этого типа напрямую. В поле
   **Название вашего сервиса** введите `Hexage`, загрузите иконку,
   укажите **Контактную почту** и нажмите **Продолжить**.
   [Форма регистрации](https://oauth.yandex.ru/client/new/id/) ·
   [Регистрация приложения](https://yandex.ru/dev/id/doc/ru/register-auth)
2. На шаге **Платформы приложения** выберите **Веб-сервисы**.
   В поле **Redirect URI** вставьте точно `http://127.0.0.1:43857/oauth`.
   Hexage принимает ответ на этом адресе во время входа. У типа
   «Для доступа к API или отладки» адрес возврата фиксирован, поэтому
   для Hexage нужна регистрация с платформой «Веб-сервисы».
   [Типы приложений](https://yandex.ru/dev/id/doc/ru/register-client) ·
   [Фиксированный адрес для отладки](https://yandex.ru/dev/id/doc/ru/register-api)
3. На шаге **Доступ к данным** найдите **Яндекс.Диск REST API** и выберите
   только **Доступ к папке приложения на Диске** (`cloud_api:disk.app_folder`).
   Нажмите **Продолжить**, затем **Всё верно**.
   [Право папки приложения](https://yandex.ru/dev/api360/doc/ru/ref/ServiceApplicationsService/ServiceApplicationsService_Create)
4. Откройте карточку созданного приложения. Скопируйте **Client ID**
   в поле `oauth.yandex.client_id`. Для Яндекса Hexage обменивает код с PKCE
   S256, поэтому **Client secret** вводить не требуется.
   [Обмен кода Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/codes/code-url)

### Запуск Hexage с настройками

При первом запуске Hexage создаёт `hexage.yaml` с пустыми полями в
пользовательском каталоге настроек. Существующий файл приложение не
перезаписывает. Откройте его в редакторе, впишите Client ID и перезапустите
Hexage. Команды ниже открывают этот файл.

**Windows, PowerShell**

```powershell
$config = Join-Path $env:LOCALAPPDATA 'Hexage\hexage.yaml'
notepad $config
```

**Linux, Bash**

```bash
config="${XDG_CONFIG_HOME:-$HOME/.config}/Hexage/hexage.yaml"
${EDITOR:-nano} -- "$config"
```

Шаблон с теми же полями — [hexage.example.yaml](hexage.example.yaml).

Вставьте Client ID в кавычки.
Поле Google `client_secret` можно оставить пустым. Пропустите раздел
ненужного провайдера или оставьте его `client_id` пустым.
Сохраните файл в UTF-8 и перезапустите Hexage обычным способом.
Путь одинаков для запуска из исходников и бинарника, включая запуск
двойным щелчком. При ошибке в YAML или невозможности создать файл Hexage
покажет предупреждение и оставит доступ к локальному хранилищу и файловому
обмену.

Для перехода со старой версии перенесите значения прежних OAuth-переменных
в соответствующие поля YAML. При переносе на другой компьютер используйте
те же Client ID и облачный аккаунт, чтобы открыть снимки из той же папки
приложения. Файл содержит открытые настройки регистрации. Храните его
в своём профиле и не добавляйте в репозиторий.

Разблокируйте хранилище, откройте **Облачное хранилище** и нажмите
**Экспортировать снимок в облако**. Выберите провайдера
и нажмите **Выбрать**. При первом обращении откроется системный браузер.
Войдите, предоставьте доступ и вернитесь в Hexage, чтобы увидеть результат.
Затем выберите того же провайдера и нажмите **Обновить список снимков**. Экспортированный
снимок должен появиться в списке. Если в Hexage доступен только файловый
обмен, проверьте путь к `hexage.yaml` и значения Client ID, затем
перезапустите приложение. Если Яндекс не возвращает в приложение, сверьте Redirect URI
в карточке регистрации со значением выше.

Если на Linux после успешного входа в браузере Hexage сообщает «Нет связи с
облачным сервисом или ответ недопустим», проверьте TLS встроенного Python:

```bash
.venv/bin/python -c "import ssl; ssl.create_default_context()"
```

Ошибка `ERROR_IN_SYSTEM_DEFAULT_CONFIG` означает, что системный
`/etc/ssl/openssl.cnf` несовместим с OpenSSL 3.5 из сборки: например,
`config_diagnostics = 1` вместе с секцией `[insta]` делает создание любого
TLS-контекста невозможным. Hexage задаёт `OPENSSL_CONF=/dev/null` до
инициализации TLS, если эта переменная не задана, и работает на таких
системах с собственными настройками TLS. Чтобы вернуть системную политику,
задайте `OPENSSL_CONF` явно перед запуском. Для сборки без этого исправления
обход — `OPENSSL_CONF=/dev/null hexage`.

Токены сохраняются через Windows Credential Manager или Linux Secret
Service, если системное хранилище доступно. Иначе токены остаются в
сессии приложения. Google использует refresh-токен, а Яндекс при истечении
токена снова открывает браузер. «Отключить аккаунт» удаляет локальные
учётные данные. Для отзыва доступа на стороне провайдера используйте
настройки соответствующего аккаунта.

Все облачные операции выполняются в окне «Облачное хранилище» (иконка облака
в главном окне). Выберите провайдера и нажмите «Обновить список снимков».
Из списка можно восстановить хранилище из выбранного снимка или удалить этот снимок.
Список показывает дату и время сохранения в облаке (UTC); дата изменения
самих данных проверяется при восстановлении. Удаление требует подтверждения
и окончательно удаляет только выбранную копию.

Кнопка облачного экспорта позволяет выбрать один или оба провайдера.
Повтор экспорта создаёт новый снимок. Отключить выбранный аккаунт
можно из того же окна.

Если ответ потерян или операция отменена во время передачи, копия могла
уже появиться у провайдера. При восстановлении на новой установке Hexage
проверяет подлинность снимка, но не может проверить, самый ли он свежий.
